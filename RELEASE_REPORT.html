This report
Every item above reflects what actually happened this session, not what the code merely allows.

Bugs found and fixed this session

  • Production build failure — stale role value. The last deploy failed type-checking because roleSchema was tightened to FRONTLINE / CLIENT_ADMIN / SUPER_ADMIN earlier this session, and the workflow builder's default-step function still hardcoded the old free-text "admin". Diagnosed from the actual Amplify build log (a TypeScript code-frame pointing at the exact line), fixed, redeployed, confirmed Deployed.
  • Copilot diff bug caught before shipping. update_step/add_step returned an identical before/after snapshot when editing an already-existing draft, because the "before" reference and the mutated object were the same JS object — the diff UI would have silently shown no change. Caught in self-review before deployment; fixed by snapshotting before mutation.
  • Mobile nav menu clipped to ~140px. Opening the hamburger menu on a narrow viewport showed only the first link in a tiny sliver instead of the full screen. Root cause: .site-nav's backdrop-filter: blur(16px) establishes a CSS containing block for position:fixed descendants, so the panel's inset:0 resolved against the header's own ~140px box instead of the viewport. Fixed by rendering the panel and overlay as siblings of the header instead of children. Verified live before and after.

The one real blocker

  • No login credentials for any AmazFlow role. I don't have — and won't attempt to create or guess — a SUPER_ADMIN, CLIENT_ADMIN, or FRONTLINE login for the real Cognito user pool. That single gap is why roughly two-thirds of the items above stop at PARTIAL instead of PASS: the code is written, deployed, and reachable, but nobody has actually clicked through it as a signed-in human this session.
  • Chrome extension end-to-end. Verifying the full agent connect/authorize/exchange chain needs a real Chrome install pointed at a real tenant — outside what this session can do on its own.

Manual verification script

Twenty minutes with a real login closes every remaining gap. Hand this to yourself or a design partner.

As a customer (FRONTLINE or CLIENT_ADMIN)

  1. Sign in at amazflow.com/login. Confirm no AWS/Cognito branding appears anywhere.
  2. Open a workflow, type a request, click Review request →. Confirm the interpretation card describes your actual words, not a placeholder.
  3. Click Let me fix this — confirm your original text is still there, editable. Change it, then confirm again — the new confirmation should reflect the edit.
  4. Click Looks right, go ahead →. Confirm the run actually starts (state leaves AWAITING_CONFIRMATION).
  5. Mid-run, click Cancel this run, confirm the dialog, confirm it actually stops (state becomes CANCELLED, not stuck spinning).
  6. Let a run complete. Confirm the evidence section shows real step results, not a generic "AmazFlow checked" line.
  7. On a brand-new account with zero runs, confirm you see "Your impact will appear here" rather than blank stat tiles.

As SUPER_ADMIN

  1. Open the Copilot panel (bottom-right ✦). Ask it to list workflows — confirm it calls a tool and answers from real data, not a guess.
  2. Ask it to change a workflow's confidence threshold. Confirm a Proposed change card appears with a real diff, and nothing changes until you click Apply.
  3. Ask "why did run fail?" on a real failed run. Confirm the answer cites specific audit events, not a plausible-sounding guess.
  4. Create a test organization, set its branding (display name, accent color), then visit /login?org=<slug> signed out. Confirm the org's name/accent appears alongside — never instead of — the AmazFlow brand.
  5. Create an agent authorization code, revoke it, confirm the extension can no longer connect with it.

As the browser agent

  1. Unzip the delivered extension, load it unpacked in chrome://extensions.
  2. Click Connect to AmazFlow →, sign in, authorize. Confirm the extension shows "Connected" with the real org name — no token was ever pasted.
  3. Trigger a workflow with a browser-provider step. Confirm the extension picks up the task and posts a result back, success or failure.

The target you set was: hand a real design partner a login, let them safely run a real workflow, see what AmazFlow understood, stop it when necessary, see evidence it actually happened, and manage the system from your own Copilot without an outside AI assistant.
